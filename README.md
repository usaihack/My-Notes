## About

This repository is a structured, long-term study record of my progression into ethical hacking and penetration testing. Every note is written from first-hand practice — no copy-pasted material — and organized around a consistent format: concept explanation, real command output, and a practical assignment tied to the topic.

The project serves two purposes:

1. **A personal learning system** — spaced, sequential, and cumulative, so each topic builds on the last.
2. **A public record of process** — for anyone assessing depth of understanding rather than a certificate alone (recruiters, peers, other learners).

**Intended audience:** beginners building a Linux/networking foundation, CTF players who want the fundamentals solid before jumping into boxes, and anyone evaluating this as evidence of consistent, self-directed technical work.

## Automation

This README updates itself. There is no manual editing of the tables above.

**How it works:**

1. A new study day gets its own file, e.g. `MONTH-02-(NETWORKING BASICS)/Day-26, Kerberos.md`.
2. That file gets pushed to `main`.
3. A [GitHub Action](.github/workflows/update-readme.yml) fires, runs [`scripts/generate_readme.py`](scripts/generate_readme.py), which:
   - scans every `MONTH-XX-(...)` folder for `Day-*.md` files,
   - sends any new or changed file to Google's Gemini API for a one-line summary of what it covers (cached, so unchanged files are never re-summarized),
   - rebuilds the Roadmap, Module Breakdown, Progress, and Directory Structure sections,
   - commits the updated `README.md` straight back to the repo.
4. It also runs once a day on a schedule and can be triggered manually from the **Actions** tab, so nothing ever goes stale even if a push is missed.

The only manual step, ever, is a one-line edit to [`scripts/config.yaml`](scripts/config.yaml) when starting a brand-new month — everything else is hands-off.

**One-time setup** (already done for this repo): a free `GEMINI_API_KEY` (from [Google AI Studio](https://aistudio.google.com/apikey), no credit card required) is stored as a repository secret under Settings → Secrets and variables → Actions, which the workflow uses to call Gemini.

## Approach

Each note follows a consistent format rather than free-form writing:

- **Concept first** — what the technology is and why it exists
- **Real output** — actual command output from practice, not textbook examples
- **Offensive and defensive framing** — how an attacker would abuse it, how a defender would detect it
- **Connections** — explicit links back to earlier topics so the material compounds rather than sitting in isolation

Notes are written independently rather than adapted from existing courses; mistakes and revisions are left in rather than cleaned up after the fact.
